# Cards Almanac — acceptance and verification

These checks are for the future implementation. They have not been run against a Cards Almanac component merely by generating this prompt package.

## Before editing

Record current working-tree differences. Compare protected file hashes in the reference baseline; save current hero and cinematic screenshots on the same viewport/device settings intended for after-comparison. A dirty baseline is valid: preserve it rather than restoring HEAD.

Find actual package scripts and current tests. Some archive/spacetime tests assert features deliberately being removed; identify them by assertion and source dependency. Replace those checks with the new section's behavior where appropriate, document retirements, and retain unrelated route/black-hole tests.

## Visual and movement matrix

Capture at 1440×900 and 1920×1366 desktop; also inspect 1280×800, 768×1024, 390×844, 320×640 and short landscape. Include 200% text/browser zoom. Original mobile geometry is unverified, so assess usability of the adaptation rather than pretending a measured mobile match.

Capture these section states at stable scroll positions:

1. Intro end → gallery heading and first card entry.
2. First card settled in the sticky stage.
3. Second card halfway over first.
4. Third card settled, with older upper bands visible.
5. Last card held before release.
6. Final release → existing Complexity scene.
7. Reverse scrolling through the same positions.
8. Project detail open, empty slot, template slot and author-supplied fixture live slot.

Also run a clearly marked six-card dev fixture and a one-card configuration. Zero cards must not allocate a giant blank scroll track. Altering descriptions should not clip text or hide plus controls.

Compare local reference frames by aspect ratio and composition: container width, cover/text proportion, whitespace, corner radii, cover crop, shadow, staggered bands, incoming overlap and gentle lean. Different artwork prevents a useful full-frame raw pixel score; use geometry or masked comparisons and disclose the distinction. Do not simply assert “pixel perfect”.

Verify settled card text is sharp. No full-section blur, wildly floating cards, giant perspective tilt, tiny backs, cropped controls, unexpected horizontal scrollbar or black unstyled gap between sections.

## Behavior and accessibility

- Normal wheel/trackpad/touch page scrolling stays native; no scroll trapping or auto-advance.
- Rapid wheel, scrollbar drag, Home/End, resize and reverse scroll produce deterministic card order and final positions.
- All titles/descriptions remain semantic DOM content available without JavaScript. Keyboard focus on a card/control reveals the relevant card rather than remaining occluded behind another one. Use explicit focus-to-card handling or an accessible list view if needed.
- Tab/Shift+Tab traversal is logical. Plus buttons have unique accessible names, visible focus and at least 44×44 CSS px touch area (proposed usability target).
- Details dialog: opens the right project, restores focus, closes via Escape/button, prevents background focus; closing returns to the same reading position.
- Empty slot is understandable and actionable only where there is a real action. No fictional live URL or misleading client claim.
- Reduced motion and Pause expose every card in a stable reading layout; toggling does not jump to an unrelated page region. Reload respects the existing pause preference where supported.
- Fixed header, bottom utilities and mobile browser chrome do not cover content/buttons. Text contrast should meet WCAG AA; images have appropriate alt or decorative handling.
- Framing fixture opens only after request; at most one embed; close unmounts it; fallback external link remains available. Test link-only policy independently of network failure.
- Intro orbit click/drag/touch/reset and intro scroll handoff still behave as before. Complexity visual framing and progression remain unchanged.

## Runtime and performance evidence

Verify the home-page import graph and mounted DOM no longer contain the archive canvas/renderer. Confirm no archive RAF/listener/debug global/query handler continues operating. Black-hole canvases are expected in their approved sections; distinguish them by owner instead of asserting zero canvases globally.

Use a production-like build for performance. Record browser, viewport, device/DPR and capture duration. Target smooth 60 Hz interaction on the tested desktop (about 16.7 ms frame budget), but report observed timing/long frames instead of guaranteeing all-device fps. No recurring gallery work at rest, offscreen or hidden; bounded layer count/memory; no React render per animation frame.

Inspect startup for hydration warnings, uncaught errors, invalid image loads and CLS. Pre-size covers, load first visible preview appropriately and lazy-load subsequent real images. Do not preload every iframe/project just to hide loading delays. Preserve current hero/cinematic rendering cost; this change should remove the archive's GPU workload, not add a second renderer.

Run `npm run check` and relevant current route/scroll/black-hole orbit checks after reviewing their actual scripts. Add focused gallery checks for reversible stack geometry, cleanup, data/readiness and dialog focus if the existing QA harness supports them. Do not write tests that merely re-state transform constants without checking behavior.

## Finish evidence

Save results, representative browser screenshots and any performance traces under `docs/research/cards-almanac/implementation/`. Record final tuned motion values, content migration, retired assertions and known substitutions. Compare protected hashes again; explain any necessary scoped shell change, and show that protected shader/intro/cinematic files remain unchanged from the implementation baseline.

A successful build alone is insufficient. Finish only when both replacement scope and visible card-stack behavior have been verified. If a check cannot run, say precisely which one and why; do not convert “not run” into “passed”.
